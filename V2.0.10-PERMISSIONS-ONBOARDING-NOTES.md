# v2.0.10 - Permissions Onboarding (20 January 2026)

## 🎯 Problem Solved

**Android WebView microphone recording was failing** after the countdown, even though:
- Permissions were granted in AndroidManifest.xml ✓
- Mic check modal showed microphone working ✓
- Stream reuse pattern implemented ✓
- Browser (desktop/iOS) worked perfectly ✓

**Root Cause**: Android's permission model requires sensitive permissions (camera, microphone) to be requested **during app onboarding**, not dynamically during features.

## ✨ Solution: Permissions Onboarding Page

Created a new **permissions-onboarding.html** page that:

1. **Requests camera + microphone upfront** - Before user can access incident reporting
2. **Shows clear explanations** - Why each permission is needed
3. **Visual feedback** - Green checkmarks when granted, red X when denied
4. **Allows skipping** - User can enable later if they prefer
5. **Tracks completion** - Uses localStorage to avoid nagging on every login

## 🔧 Technical Implementation

### New File: `public/permissions-onboarding.html`
- Beautiful UI matching app design
- Requests both permissions with proper explanations
- Shows permission status (pending ⏳, granted ✓, denied ✕)
- Immediately stops streams after permission granted (just needed permission)
- Redirects to incident.html after completion

### Modified: `public/login.html` (lines 556-580)
- Checks if user has completed permissions onboarding
- First-time users → Redirected to `/permissions-onboarding.html`
- Returning users → Normal redirect flow
- Users with specific destination → Skip onboarding (respect their intent)

### Key Logic:
```javascript
// Check if user has completed permissions onboarding
const hasCompletedPermissions = localStorage.getItem('permissions_onboarding_complete');

// Redirect to permissions onboarding for first-time users
let redirectUrl;
const requestedUrl = getRedirectUrl();

if (!hasCompletedPermissions && requestedUrl === '/index.html') {
    // First-time user without specific destination = show permissions onboarding
    redirectUrl = '/permissions-onboarding.html';
    console.log('First-time user detected, redirecting to permissions onboarding');
} else {
    // User has completed onboarding OR has a specific destination
    redirectUrl = requestedUrl;
}
```

## 🔒 Android Permission Best Practice

**WHY THIS WORKS:**

1. **Early Request** = Android expects permissions during onboarding
2. **User Context** = User understands why app needs these permissions
3. **Session Persistence** = Permissions granted early stay valid throughout session
4. **No Revocation** = Android doesn't revoke permissions due to page visibility changes
5. **WebView Stability** = MediaStream tracks stay "live" because permission is established

**BEFORE (BROKEN):**
```
Login → Incident Page → User clicks record → Mic check modal → getUserMedia()
        ↑ No permissions yet                                    ↑ Android confused
```

**AFTER (FIXED):**
```
Login → Permissions Onboarding → getUserMedia() for camera + mic
        → Incident Page → Mic check reuses existing permission
        → Recording reuses existing permission
        ↑ Permissions established early, stay valid
```
